=== Ransomware-Resilienz



==== Erweiterte Konfiguration der isolierten Wiederherstellungsumgebung

Ransomware Resilience bietet jetzt einen verbesserten Workflow zur Konfiguration isolierter Wiederherstellungsumgebungen. Der neue Workflow vereinfacht und präzisiert den Prozess zur Einrichtung einer solchen Umgebung für Cloud- oder On-Premises-Umgebungen.

Weitere Informationen finden sich unter link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/task-clean-restore.html["Eine isolierte Wiederherstellungsumgebung für eine saubere Wiederherstellung bereitstellen"^].



==== Verbesserter Workflow zur Aktivierung der Benutzeraktivitätsüberwachung

Ransomware Resilience hat den Workflow für die Aktivierung der Benutzeraktivitätsüberwachung verbessert. Bisher testete Ransomware Resilience die Verbindung des Datensammlers jedes Mal, wenn Sie für eine Workload eine Ransomware-Schutzstrategie mit Benutzeraktivitätsüberwachung aktivierten. Mit diesem Update wird diese Prüfung nun übersprungen, wenn für die Storage VM ein Datensammler vorhanden ist und sich im Status "running" befindet, wodurch der Schutz Workflow beschleunigt wird.

Weitere Informationen finden Sie unter link:link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/rp-use-protect.html["Workloads schützen"^].



==== Google Cloud NetApp Volumes Flex Service Level allgemein verfügbar

Die Unterstützung für das Flex Service Level von Google Cloud NetApp Volumes in Ransomware Resilience ist jetzt allgemein verfügbar (GA).

=== Cloud Volumes ONTAP



==== Cloud Volumes ONTAP 9.19.1 in Azure

Sie können jetzt die NetApp Console verwenden, um die Version mit allgemeiner Verfügbarkeit (GA) von Cloud Volumes ONTAP 9.19.1 in Azure einzusetzen und zu managen.

Die Console unterstützt Cloud Volumes ONTAP 9.19.1 in AWS und Google Cloud seit August 2026.

https://docs.netapp.com/us-en/cloud-volumes-ontap-relnotes/reference-new.html["Cloud Volumes ONTAP 9.19.1 Versionshinweise"^]



==== Azure Verschlüsselung auf Hostebene für Cloud Volumes ONTAP

Ab Cloud Volumes ONTAP 9.19.1 GA ist die Azure-Verschlüsselung auf Hostebene standardmäßig für neue Azure-Einzelknoten- und Hochverfügbarkeits-Deployments (HA) aktiviert, die die Voraussetzungen erfüllen. Diese Funktion verschlüsselt Daten auf dem physischen Server, auf dem die VM ausgeführt wird, einschließlich des ephemeren Datenträgers und der zugehörigen Caches auf Hostebene, während die Daten auf den Host geschrieben und von ihm gelesen werden.

Vor dem Deployment von Cloud Volumes ONTAP in Azure muss Ihre Umgebung die folgenden Voraussetzungen erfüllen:

* Die `EncryptionAtHost`Funktion ist für Ihr Azure-Abonnement registriert. Weitere Informationen finden Sie unter https://learn.microsoft.com/en-us/azure/virtual-machines/linux/disks-enable-host-based-encryption-cli["Microsoft-Dokumentation: Aktivierung der Verschlüsselung auf dem Host"^].
* Der von Ihnen ausgewählte VM-Instanz Typ unterstützt die Verschlüsselung auf dem Host in Ihrer Azure-Region. Weitere Informationen finden Sie unter https://learn.microsoft.com/en-us/azure/virtual-machines/linux/disks-enable-host-based-encryption-cli#finding-supported-vm-sizes["Microsoft Dokumentation: Unterstützte VM-Größen ermitteln"^].


Folgende Punkte sind zu beachten:

* Es ist keine zusätzliche Konfiguration erforderlich.
* Wenn diese Voraussetzungen nicht erfüllt sind, ist die Azure-Verschlüsselung auf Hostebene für Ihr Cloud Volumes ONTAP Deployment nicht aktiviert.
* Die Host-Verschlüsselung gilt nur für Azure, nicht für AWS oder Google Cloud.


Microsoft Dokumentation: https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal["Die Ende-zu-Ende-Verschlüsselung lässt sich im Azure-Portal mithilfe der Verschlüsselung auf dem Host aktivieren"^]



==== Backend-Netzwerkverschlüsselung auf Cloud Volumes ONTAP Clustern in Azure und Google Cloud

Cloud Volumes ONTAP 9.19.1 und höher unterstützen die Netzwerkverschlüsselung des Backend-Clusters für HA-Konfigurationen in Azure und Google Cloud.

Die Aktivierung der Clusternetzwerkverschlüsselung kann sich auf die Cluster-Performance auswirken. Vor der Aktivierung dieser Funktion ist Vorsicht geboten, und es sollte überprüft werden, ob Ihre Umgebung den zusätzlichen Aufwand bewältigen kann.

https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-enable-cluster-encryption.html["Backend-Netzwerkverschlüsselung auf Cloud Volumes ONTAP Clustern aktivieren"^]



==== Fähigkeit zur Reduzierung von Unterbrechungen während der geplanten Azure Wartung

Während geplanter Wartungsarbeiten kann Azure eine VM in einem Cloud Volumes ONTAP HA Paar kurzzeitig anhalten. ONTAP könnte die Pause als Knotenausfall interpretieren und Storage-Vorgänge auf den Partnerknoten verlagern, um sie nach dem Fortsetzen der VM wieder zurückzuverlagern (Takeover und Giveback). Dieser Vorgang kann aktive Clientverbindungen unterbrechen, selbst wenn kein Knotenausfall vorliegt.

Mit Cloud Volumes ONTAP 9.19.1 und höher lässt sich eine optionale Einstellung aktivieren, mit der das HA-Paar eine geplante Azure-Wartungssperre ohne automatisches Takeover und Giveback weiter durchlaufen kann.


NOTE: Diese Funktion ist als öffentliche Vorschau mit Cloud Volumes ONTAP 9.19.1 verfügbar.

https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-azure-prevent-freeze.html["Vermeidung von Unterbrechungen während der Azure-Wartung für Cloud Volumes ONTAP HA-Paare"^]

In dieser Version werden für Hyper-V-Workloads die folgenden Verbesserungen eingeführt:

[[disaster-recovery]]
=== Notfallwiederherstellung



==== Optionale Startreihenfolge für Kubernetes Ressourcengruppen

NetApp Disaster Recovery unterstützt jetzt die optionale Festlegung der Startreihenfolge für Ressourcengruppen in einem Kubernetes Replikationsplan, indem eine Prioritätsreihenfolge und eine optionale Verzögerungszeit für Ressourcen angegeben werden. Mit dieser Option können Ressourcen bei Bedarf gleichzeitig gestartet und der Start von Ressourcen verzögert werden, die von anderen abhängig sind, sodass Ihre Anwendungen in einem fehlerfreien Zustand wieder online gehen können.

Weitere Informationen finden Sie unter link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/drplan-create.html["Erstellen eines Replikationsplans"^].



==== SnapLock Volume-Unterstützung

Disaster Recovery unterstützt jetzt SnapLock Volumes, sodass ein Failover manipulationssicherer Snapshots möglich ist. Bei einem Failback mit SnapLock Volumes muss die Option *Take snapshot now* verwendet werden, damit das Failback erfolgreich abgeschlossen wird.

Weitere Informationen sind in den Anweisungen für link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/failover.html["Failover"^] und link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/failback.html["Failback"^] enthalten.



==== Vereinfachte Aktualisierungs- und Compliance-Ausführungen

Aktualisierungsläufe für vCenter, Replikationspläne und Compliance wurden zu einem einzigen Auftrag vereinfacht, um eine schnellere Ausführung zu ermöglichen. Um diese Änderung zu sehen, finden Sie Informationen dazu unter link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/monitor-jobs.html["Jobs überwachen"^].



==== Kubernetes Compliance-Prüfungen

Disaster Recovery hat Compliance-Prüfungen hinzugefügt, um fehlende Arbeitsumgebungen für Kubernetes Workloads zu identifizieren. Diese Compliance-Prüfungen tragen dazu bei, den Systemstatus der Workloads sicherzustellen, damit die Integrität Ihrer Replikationspläne gewahrt bleibt.

==== ONTAP Volumes Workloads-Verbesserungen

In dieser Version führt ONTAP Volumes Workloads die folgenden Vorschauverbesserungen ein:

* *Verbesserte Unterstützung für Dark Sites*: NetApp Backup and Recovery for dark sites bietet jetzt dieselben ONTAP Volumes Datenschutzfunktionen wie NetApp Backup and Recovery. Während eines Upgrades bleiben vorhandene Datenbankdaten erhalten und werden automatisch migriert. [[cloud-volumes-ontap]]
=== Cloud Volumes ONTAP



==== Unterstützung für kapazitätsbasierte Lizenzen in Private-Mode-Bereitstellungen

Cloud Volumes ONTAP Systeme können jetzt im privaten Modus mit kapazitätsbasierten Lizenzen in AWS, Azure und Google Cloud bereitgestellt werden.

NetApp unterstützt nur das Essentials Paket für kapazitätsbasierte Lizenzierung im privaten Modus. Ein kapazitätsbasiertes Bring-Your-Own License (BYOL) Essentials Paket kann von NetApp erworben und während der Bereitstellung dem System zugewiesen werden. Die ersten 500 GiB verbrauchter Kapazität werden nicht auf Ihre Lizenzgebühren angerechnet. Zusätzliche Pakete können erworben werden, wenn der Bedarf an Arbeitslasten steigt.

NetApp empfiehlt die kapazitätsbasierte Lizenzierung für alle Cloud Volumes ONTAP Bereitstellungen im privaten Modus. Wenn bereits Bereitstellungen im privaten Modus mit knotenbasierten Lizenzen vorhanden sind, ist eine Umstellung auf kapazitätsbasierte Lizenzierung durch den Erwerb eines Essentials-Pakets von NetApp möglich. Diese neue Bereitstellungsfunktion, kombiniert mit der Umstellungsoption, unterstützt den Plan von NetApp, schrittweise von knotenbasierter auf kapazitätsbasierte Lizenzierung überzugehen.

==== Protokollierung von Benutzeraufträgen

NetApp Disaster Recovery hat die Nachvollziehbarkeit und Prüfbarkeit von Jobs durch die benutzerbezogene Job-Protokollierung verbessert. Jeder ausgeführte Job zeichnet nun den Benutzer auf, der ihn initiiert hat, wodurch ein klarer Audit-Trail für Compliance- und Fehlerbehebungszwecke entsteht. Jobs, die automatisch von NetApp Disaster Recovery ausgelöst werden, sind als „system“ gekennzeichnet, sodass sich benutzerinitiierte und dienstinitiierte Aktivitäten leicht unterscheiden lassen.

Weitere Informationen sind unter link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/monitor-jobs.html["Überwachung von NetApp Disaster Recovery-Aufträgen"^] zu finden.



==== Leistungs- und Ressourcenoptimierung

Es wurden diverse Verbesserungen im Hintergrund vorgenommen, um den Gesamtressourcenverbrauch des Systems zu reduzieren und die Leistung bei Disaster Recovery-Operationen zu steigern.

==== Konfigurationen für Cloud Volumes ONTAP in Microsoft Azure beheben, verwerfen und reaktivieren

Das übersichtliche Dashboard in NetApp Console bietet jetzt die Möglichkeit, Konfigurationsempfehlungen für Ihre Cloud Volumes ONTAP Systeme zu beheben.

Sie können auch eine oder mehrere Konfigurationen von der Analyse der optimalen Architektur ausschließen. Dadurch ist es möglich, bestimmte Konfigurationen zu ignorieren, die für Ihre Umgebung nicht zutreffen.

Wenn Sie eine verworfene Konfiguration später wieder einbinden möchten, können Sie sie im Well-Architected Dashboard reaktivieren. Dadurch wird die Konfiguration in die Analyse zurückgeholt und es werden Empfehlungen und Korrekturen dafür bereitgestellt.
